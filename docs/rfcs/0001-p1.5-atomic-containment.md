- **Status**: PROPOSED / ACTIVE SPIKE
- **Author**: Plug Core Security Engineering
- **Created**: 2026-10-10
- **Target Branch**: `feat/p1.5-atomic-containment`
- **Baseline Commit**: `48e54a0` (`docs(security): formalize P1 defense-in-depth boundary and P1.5 atomic containment roadmap`)

## 1. Executive Summary & Context

Plug's P1 release established a robust **defense-in-depth** capability sandbox for WebAssembly plugins (`fs_scoped`):
- Opaque preopened directory mapped to `/data` (`~/.plug/data/<plugin_hash>/`)
- Manifest import filtering and runtime descriptor capability checks
- Lexical boundary validation rejecting rooted paths and escaping `..`
- Reparse dereference inhibition at target (`FILE_FLAG_OPEN_REPARSE_POINT` / `O_NOFOLLOW`)
- Kernel handle interrogation post-open (`GetFinalPathNameByHandleW` / `/proc/self/fd/`)
- Deferred truncation (`file.set_len(0)` post-validation) and total elimination of foreign deletion routines

While P1 effectively eliminates accidental leaks and static symlink escapes, it operates on a **check-then-open** + **post-open verification** pattern. This leaves a theoretical TOCTOU race window where a concurrent process or filesystem filter mutates intermediate directory components while resolution is in flight.

The objective of **P1.5** is to eliminate intermediate namespace race windows through **atomic kernel-level containment primitives** on Linux and **verified handle-pinned operations** on Windows, without relying on naive path-string fallbacks.

## 2. Threat Model

### 2.1 Attacker Profile
An untrusted or compromised WebAssembly plugin executing inside Wasmer Cranelift runtime with `fs_scoped` storage permission, potentially coordinated with concurrent background threads or host-level filesystem mutations.

### 2.2 Attack Vectors Addressed in P1.5
1. **Intermediate Component Rename Race**:
   An attacker initiates `path_open("subdir/target.txt")`. Between the runtime's component check of `subdir` and the kernel's open, `subdir` is renamed or swapped to point outside `/data`.
2. **Path-Based Unlink / Rmdir Race**:
   Runtime validates that `target_path` is within `/data`, but before `unlink(target_path)` executes, `target_path` or an intermediate parent is swapped to a critical host file.
3. **Multi-Component Directory Creation Escape**:
   Calling `mkdir("a/b/c")` where intermediate components traverse outside the root.
4. **Magic-Link Traversal Escape**:
   Traversing pseudo-filesystem magic links (e.g. Linux `/proc/self/fd/...` or Windows `\??\...`).
5. **Pre-Verification Destructive Side-Effects**:
   `O_CREAT` or `O_TRUNC` racing to create or overwrite a host file before detection.

### 2.3 Invariant Boundary: Inode Binding vs. Host Namespace Reparenting
Pinned directory descriptors (`parent_dfd`) bind to the underlying filesystem inode in the kernel VFS. `openat2` guarantees that path resolution remains strictly confined beneath `dirfd` during lookup. Once opened, relative operations (`unlinkat`, `mkdirat`) execute directly against the bound inode.
If a privileged external host process moves or reparents an ancestor directory outside `/data` after the descriptor is opened, the descriptor continues referencing that filesystem object.
- **Guest Plugin Boundary**: Plug's capability sandbox strictly confines untrusted guest plugins and concurrent guest threads against escaping `/data`.
- **Pinned Descriptors**: Eliminate intermediate pathname resolution races for all guest-initiated and unprivileged operations.
- **Host Process Boundary**: Privileged external host processes with filesystem modification rights outside `/data` belong to the host Trusted Computing Base (TCB); protection against host-level namespace reparenting is outside the guest capability sandbox boundary.

## 3. Non-Negotiable Security Invariants

1. **Strict Tree Confinement**:
   Every filesystem operation executed on behalf of a guest must resolve strictly beneath the directory descriptor capability representing `/data`. Any resolution escaping the tree must fail immediately.
2. **Zero Pre-Verification Side-Effects**:
   No host file outside `/data` may be created, truncated, modified, or deleted even if a concurrent race occurs during resolution.
3. **Fail-Closed Policy (Deliberate Security Denial)**:
   If atomic containment primitives (e.g. Linux `openat2`) are unavailable, unsupported by the kernel (< 5.6), or blocked by seccomp (`ENOSYS`), the engine strictly denies capability access with `WASI_ENOTCAPABLE` (`76`). This is an intentional security policy decision: because containment cannot be mathematically guaranteed without atomic kernel primitives, Plug denies capability access rather than falling back to uncontained path resolution.
4. **Single-Leaf Mutation on Pinned Parent**:
   Mutating operations (`mkdir`, `unlink`, `rmdir`) must never be dispatched with multi-component path strings. The parent directory descriptor must be safely opened and pinned first; the mutation is dispatched strictly as a single leaf component on the verified parent descriptor.
5. **No Universal Race Detector Fallacy**:
   `openat2` returns `EAGAIN` only in specific kernel race scenarios during resolution. It is not an omniscient race detector. Bounded retries must be enforced; persistent races return WASI `EAGAIN` (`6`) or fail-closed `ENOTCAPABLE` (`76`).

## 4. Linux Architecture & Implementation

### 4.1 Native Primitive: `openat2(2)`
Linux kernel 5.6+ introduces `openat2`:
```c
int openat2(int dirfd, const char *pathname, struct open_how *how, size_t size);
```

#### Resolution Flags (`open_how.resolve`):
- `RESOLVE_BENEATH`: Prevents resolution from walking outside the directory tree rooted at `dirfd`. Any `..` that would exit `dirfd` or absolute symlink returns `EXDEV` or `EACCES`.
- `RESOLVE_NO_MAGICLINKS`: Blocks traversal of magic links (e.g., `/proc/self/fd/...`).
- `RESOLVE_NO_SYMLINKS`: Disallows symlink traversal completely (aligned with Plug's policy of zero symlink creation).

#### Race Handling:
If the kernel detects a concurrent rename that prevents it from guaranteeing `RESOLVE_BENEATH` containment, it returns `EAGAIN`.
- **Plug Policy**: Maximum 3 bounded retries following initial failure (total 4 attempts) with thread yield backoff. If `EAGAIN` persists, return WASI `EAGAIN` (`6`) or fail-closed `ENOTCAPABLE` (`76`).

### 4.2 Mutating Primitives: `mkdirat` and `unlinkat`
Because POSIX `mkdirat` and `unlinkat` do not accept `open_how` resolution flags:
1. For multi-component path `a/b/c`:
   Open parent directory `a/b` via `openat2(dirfd, "a/b", open_how { flags: O_PATH | O_DIRECTORY | O_CLOEXEC, resolve: RESOLVE_BENEATH | RESOLVE_NO_MAGICLINKS | RESOLVE_NO_SYMLINKS })`.
2. Verify parent descriptor `parent_dfd`.
3. Dispatch single-component operation on `parent_dfd`:
   - `mkdirat(parent_dfd, "c", mode)`
   - `unlinkat(parent_dfd, "c", 0)` (file)
   - `unlinkat(parent_dfd, "c", AT_REMOVEDIR)` (directory)
4. Because the target is a single leaf component relative to an already-pinned directory descriptor, no intermediate traversal races are possible.

## 5. Windows Architecture (Independent Feasibility Track)

Windows Win32 API does not have an equivalent to `openat2(RESOLVE_BENEATH)`. `FILE_FLAG_OPEN_REPARSE_POINT` only inhibits dereferencing on the terminal object.

### 5.1 Native NT Primitive Investigation
1. **Verified Root Handle**:
   Preopened directory descriptor holds an authentic Win32/NT `HANDLE` opened with `FILE_FLAG_BACKUP_SEMANTICS`.
2. **Incremental Component Walking & Pinning**:
   To traverse `a/b/c`:
   - Open component `a` relative to root handle using `FILE_FLAG_OPEN_REPARSE_POINT | FILE_FLAG_BACKUP_SEMANTICS`.
   - Verify handle identity via `GetFinalPathNameByHandleW` and assert `FILE_ATTRIBUTE_REPARSE_POINT` is absent.
   - Pin handle `h_a` and open `b` relative to `h_a`.
   - Pin handle `h_b` as parent handle.
3. **Handle-Directed Atomic Deletion**:
   To delete `c`:
   - Open leaf `c` relative to `h_b` with `DELETE` access and `FILE_FLAG_OPEN_REPARSE_POINT`.
   - Verify leaf handle is beneath root and not a reparse point.
   - Execute deletion directly on the open handle:
     ```rust
     SetFileInformationByHandle(
         h_file,
         FileDispositionInfo,
         &FILE_DISPOSITION_INFO { DeleteFile: TRUE },
         std::mem::size_of::<FILE_DISPOSITION_INFO>() as u32
     );
     ```
   - Closing the handle commits deletion without any pathname lookup race.

### 5.2 Filesystem & Platform Parity Policy
- Windows feasibility must be tested on NTFS.
- If Windows cannot achieve identical kernel-level atomic invariants as Linux `openat2`, **do not force an inaccurate unified abstraction**. Document the platform difference explicitly in `SECURITY.md`.

## 6. WASI Errno Mapping Specification (Official wasi-libc Preview 1 Alignment)

| Failure Scenario | Native Errno / Condition | Mapped WASI Errno | Description |
|---|---|---|---|
| Traversal exceeds root | `EXDEV` / root escape | `ENOTCAPABLE` (`76`) | Path resolution crossed containment boundary |
| Symlink / Magiclink policy violation | `ELOOP` | `ENOTCAPABLE` (`76`) | Disallowed symlink / magiclink encountered |
| Missing component | `ENOENT` | `ENOENT` (`44`) | Target does not exist |
| Permission denied (DAC/ACL) | `EACCES` | `EACCES` (`2`) | Operating system denied access |
| Operation not permitted | `EPERM` | `EPERM` (`63`) | Host operation not permitted |
| Target already exists | `EEXIST` | `EEXIST` (`20`) | Cannot overwrite existing file or directory |
| Invalid argument / flags | `EINVAL` | `EINVAL` (`28`) | Invalid flags, syntax, or mode |
| Directory / File type mismatch | `EISDIR` | `EISDIR` (`31`) | Is a directory when file expected |
| Not a directory | `ENOTDIR` | `ENOTDIR` (`54`) | Prefix component is not a directory |
| Directory not empty | `ENOTEMPTY` | `ENOTEMPTY` (`55`) | Cannot rmdir non-empty directory |
| Concurrent rename race | `EAGAIN` (exhausted after 1 initial + 3 retries = 4 total attempts) | `EAGAIN` (`6`) | Kernel could not guarantee containment |
| Unsupported primitive | `ENOSYS` (kernel < 5.6) | `ENOTCAPABLE` (`76`) | Intentional fail-closed policy denial (0 fallback) |
| Generic filesystem I/O error | Fallback | `EIO` (`29`) | Unhandled OS error (wasi-libc EIO = 29) |

## 7. Mandatory Acceptance Criteria (8 Verification Gates)

A P1.5 implementation must satisfy all 8 acceptance tests before consideration for trunk:

1. **Standard In-Capability I/O**: Valid CRUD operations inside `/data` pass cleanly (`PASS`).
2. **Rooted & Traversal Rejection**: Rooted paths (`/`, `\`, `C:`) and `..` escaping root fail closed with `ENOTCAPABLE` (`DENY`).
3. **Symlink & Magic-Link Invalidation**: Traversing symlinks or magic-links (`/proc/self/...`) fails closed (`DENY`).
4. **Safe Parent Open & Leaf Unlink**: Multi-component paths resolve parent safely and unlink single leaf without race (`PASS`).
5. **Multi-Component Outside Traversal**: `mkdir` / `unlink` attempting to traverse outside returns `ENOTCAPABLE` (`DENY`).
6. **Destructive Mutation Confinement**: `O_CREAT | O_TRUNC` racing across symlinks never damages outside sentinel (`PASS`).
7. **Concurrent Namespace Mutation Integrity**: Concurrent rename/symlink stress fuzzing test (500 iterations against active background mutation thread) verifies that outside sentinel remains intact (`HOST_SACRED_SENTINEL_DATA`) and records metrics (`attempts`, `safe_opens`, `denied_confined`, `mutations`). This provides empirical evidence under aggressive scheduling races, while recognizing that empirical concurrency fuzzing is not a formal mathematical proof of impossibility under all conceivable kernel thread interleavings (`PASS`).
8. **Primitive Inavailability Fail-Closed**: In environments where `openat2` returns `ENOSYS`, operations fail closed with `ENOTCAPABLE`, never falling back to unsafe path string checks (`FAIL-CLOSED`).
